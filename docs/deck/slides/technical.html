THE FOUR MODULES

M0 · UNDERSTAND

Sentence spans with stable IDs, then one fact index. Every field cites the spans it came from.

M1 · TRANSFORM

One spec per format: role, content plan, limits, JSON schema. Generators read the index, never the raw source.

M2 · VERIFY & REPAIR

Deterministic checks, then one targeted revision carrying the findings. Two model calls, never three.

M3 · PROVE

Claims resolve to source spans; each audit row carries the hash of the one before it.

EVERY DRAFT IS CHECKED IN CODE

  • Schema — the content parses against the format's schema
  • Identifiers — every number, CVE, IP and domain in a claim appears in the span it cites
  • Hedges — a hedged source cannot become a certain claim
  • Severity — one canonical value across every artefact
  • Constraints — lengths, counts, emoji, script, durations
  • Grounding — a fact must share a term with the span it cites

A failure triggers one targeted revision carrying the exact findings — never a blind retry.

SOVEREIGNTY, STATED CORRECTLY

Ingress — Tailscale decides which devices reach the gateway.

Egress — a classification check in worker code, before the adapter is chosen.

Public → cloud provider

Internal → cloud, identifiers masked, then restored

Restricted → on-device model only

The worker holds the only path out of the host. That one arrow is what the rule governs — not a setting a user can flip.

The model is one component. Around it is a pipeline: understand the source once, write every format from the same facts, check every sentence in code, and prove where it came from. Point at the worker box. That is where the egress gate lives — a classification check in code, before any provider is chosen. Tailscale controls which devices can reach us; it has nothing to do with where our data goes. Those are two different controls and we state them separately, because a security-literate judge will test that. The checks in the middle column are ordinary code, not a second model grading the first. That matters: a model asked to grade a model can be wrong in the same direction twice. If asked why the orchestrator is not itself a model: because the source document is untrusted input. A model that chooses the next step can be steered by the document it is reading, and that model would be sitting directly on top of the egress decision.
